Case Study
● Machine Learning + Full-Stack Waste Optimization for Sri Lanka

Predicting Sri Lanka's municipal garbage demand before bins overflow.

Municipal councils currently rely on static schedules regardless of real fluctuations: weekends, official Poya holidays, weather, and population density. Kasala.lk bridges this gap with a Random Forest predictive engine, 7-day rolling forecasts, citizen reporting, and an administrative feedback loop.

Section 08

All 5 Deployment Hurdles & Resolutions

Railway Build Crash

Windows-Only Package Crash

Running pip freeze on Windows captured OS-specific packages that broke the Linux build on Railway.

Manually wrote a minimal, cross-platform requirements.txt.
Runtime Exception

FileNotFoundError: model.pkl

.gitignore excluded all .pkl files, including required runtime model files.

Scoped .gitignore to only exclude ml/*.pkl and committed backend/model/*.pkl.
404 Asset Error

Images 404 in Production

Case-sensitivity mismatch (Logo.png vs logo.png); Windows ignored case while Linux on Vercel failed.

Renamed all assets to match code references exactly.
Network Error

Relative Path API Failure

Missing https:// scheme in API_URL caused calls to resolve as relative Vercel paths.

Added full https:// prefix to the backend URL constant.
Mobile Safari Glitch

bg-fixed Background Broken

Fixed-attachment backgrounds render inconsistently on mobile browsers, especially iOS.

Applied md:bg-fixed for desktop-only and normal scroll on mobile.
Section 10

Known Gaps & Future Roadmap

Admin Authentication
Currently open URL access without auth. Needs Supabase Auth protection before public municipal deployment.
Retraining with Real Logs
Model currently runs on synthetic data. Integrating actual logged weights will elevate accuracy over time.
Live Weather API
Forecast rainfall is currently a placeholder. Connecting OpenWeatherMap will enable true dynamic forecasts.
Tighten Supabase RLS
Row Level Security is currently set to permissive development mode; requires role-based access rules.
Database-Driven Calendars
Poya days and zone populations are currently in main.py. Moving to PostgreSQL allows live updates without deploys.
